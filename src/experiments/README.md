# Parameter Experiments for Workshop

## Что было добавлено

В проект `workshop` был добавлен модуль параметрического тестирования LLM-ответов.  
Цель доработки — не просто отправлять один запрос в модель, а автоматически прогонять набор тестов на нескольких конфигурациях параметров и сравнивать результаты.

Основная идея:
- взять один датасет тестовых кейсов;
- взять несколько профилей параметров модели;
- прогнать каждый тест на каждом профиле;
- сохранить ответы модели;
- автоматически оценить результат;
- собрать отчет по качеству и скорости.

---

## Что было изменено

### 1. Добавлен модуль `src/experiments`
В проект добавлен отдельный блок для экспериментов:

- `src/experiments/runner.py` — запускает тесты;
- `src/experiments/scoring.py` — оценивает ответы модели;
- `src/experiments/storage.py` — сохраняет результаты в SQLite;
- `src/experiments/report.py` — формирует CSV и Markdown-отчет.

Runner отправляет запросы в существующий endpoint `/v1/chat/completions`, получает ответы модели, считает score и сохраняет результаты. :contentReference[oaicite:0]{index=0}

### 2. Добавлены датасеты тестов
Добавлены JSON-файлы с тест-кейсами в `src/experiments/datasets/`.

Тесты покрывают разные типы задач:
- алгоритмы;
- структуры данных;
- генерацию кода;
- текстовые ответы;
- JSON-формат;
- задачи на инструкции и форматирование.

Примеры задач:
- число Фибоначчи через рекурсию;
- число Фибоначчи через динамическое программирование;
- алгоритм Евклида;
- BFS и DFS;
- бинарный поиск;
- текст о Пушкине;
- сравнение стека и очереди;
- JSON по задаче о кратчайшем пути.

### 3. Добавлены профили параметров
Добавлены конфиги в `src/experiments/configs/`.

Каждый профиль хранит набор `runtime_params`, например:
- `temperature`
- `top_p`
- `top_k`
- `num_predict`
- `seed`
- `think`

Во время эксперимента runner берет конфиг, подставляет его в запрос и прогоняет все тесты на этом профиле. Это видно по формированию `payload["runtime_params"]` в runner. :contentReference[oaicite:1]{index=1}

### 4. Реализовано автоматическое оценивание
В scoring добавлены проверки на:
- непустой ответ;
- точное совпадение;
- наличие нужных подстрок;
- отсутствие запрещенных слов;
- соответствие regex;
- валидность JSON;
- наличие обязательных ключей;
- минимальную и максимальную длину ответа.

Таким образом, оценивание работает автоматически и не требует ручной проверки каждого ответа.

### 5. Добавлено сохранение результатов
Каждый прогон сохраняется в SQLite и дополнительно экспортируется в CSV и Markdown-отчет.

Для каждого результата сохраняются:
- `test_id`
- `config_name`
- входной текст
- ответ модели
- score
- pass/fail
- latency
- `thread_id`
- `trace_id`
- `runtime_params`

В runner это формируется в объекте `row`, который потом сохраняется в БД и попадает в итоговые отчеты.

## Как работает решение

Алгоритм работы:

1. Загружается dataset из JSON.
2. Загружаются все конфиги параметров из папки `configs`.
3. Для каждой конфигурации и для каждого теста формируется запрос к `/v1/chat/completions`.
4. Модель возвращает ответ.
5. Ответ проходит через `score_response(...)`.
6. Результат сохраняется в SQLite.
7. После завершения прогона создаются:
   - `results.csv`
   - `summary.md`

Внутри `runner.py` это реализовано в функции `run_experiment(...)`. :contentReference[oaicite:3]{index=3}
